# 📦 RO-Ragexe
> An automated downstream pipeline engine designed to ingest verified distribution URLs, stream compressed asset layers, and perform isolated extractions of pristine client executables (`ragexe.exe`).

![Python](https://img.shields.io/badge/Language-Python_3.12-blue?style=for-the-badge&logo=python)
![Pipeline](https://img.shields.io/badge/Data__Pipeline-Downstream__Consumer-orange?style=for-the-badge)

The **RO-Ragexe** utility serves as an automated data harvesting mechanism inside the Ragnarok Online emulation and reverse-engineering research ecosystem. By feeding off live endpoints generated by the upstream `RO-Setup-Finder` module, this system isolates, extracts, and catalogs unpatched, factory-clean executables. These binaries are vital for packet structure validation, memory structure diffing, and maintaining synchronization updates within emulators like `rAthena` and `Hercules`.

---

## 🛠️ Architecture & Data Pipeline Flow

The extraction process operates via a decentralized, scheduled cloud framework:


```

[ RO-Setup-Finder ] (Upstream Link Registry)
│
▼ (Fetch raw links via HTTPS)
[ RO-Ragexe Automation ]
│
├──► Stream Chunked Target ZIP (No Full Disk Persistence)
├──► Local Multi-Format Regex Name Scan
├──► Isolate Binary: ragexe.exe / ragexe_re.exe / sakexe.exe
└──► Cache Registry Update & Temporary File Purge

```

### ⚡ Technical Implementation Details

* **Asynchronous Chunked Streaming:** Large-archive downloads are handled via `aiohttp` using memory-efficient chunk streaming (`iter_chunked(1024 * 1024)`). This prevents high RAM saturation and disk page faults within isolated virtual environments.
* **Smart Cache Indexing:** Includes a persistence registry (`processed_links.json`). If a remote URL hash or link matches an already index-completed record, the engine short-circuits execution via an early `[JUMP]` command, mitigating redundant network round-trips ($O(1)$ lookups).
* **Isolated File Purge:** To meet the continuous integration environment space constraints, the temporary master compressed files are immediately garbage-collected (`Path.unlink`) as soon as the target file boundary stream ends.
* **Rate-Limit Guard:** Enforces a rigid concurrency throttle (`asyncio.Semaphore(1)`) matched with a `1.0s` sleep cycle to comply with remote webserver connection profiles and ensure consistent task delivery.

## 📅 Automated Execution Loop

The integration suite handles asset updates sequentially using cross-repository tracking:

The native GitHub Actions workflow (`.github/workflows/main.yml`) executes on a monthly schedule on the **1st of every month at 02:00 AM UTC** (`0 2 1 * *`). This is purposefully configured to execute exactly **2 hours after** the upstream link finder updates its global state file, ensuring a flawless data handover sequence.

## 🚀 Environment Setup & Deployment

### Prerequisites
* Python `3.9+` (Fully optimized for `3.12`)
* Local dependency packages listed in `requirements.txt`

### Local Execution Instructions
1. Clone the repository structure down to your environment:
```bash
   git clone https://github.com/AoShinRO/RO-Ragexe.git
   cd RO-Ragexe

```

2. Fetch the upstream dynamic endpoint registry manually:
```bash
curl -o links_validos.md https://raw.githubusercontent.com/AoShinRO/RO-Setup-Finder/refs/heads/main/links_validos.md

```


3. Execute the automated extraction pipeline:
```bash
python3 ragexe_extractor.py

```


4. All successfully extracted binary assets will reside cleanly sorted inside `\ragexe_files\`.
